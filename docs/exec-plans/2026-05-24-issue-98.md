# Issue #98: [bug] 채팅 전송 실패 시 /login → /chat 리다이렉트 루프

> https://github.com/GreenBrain-Inha/FE_GreenBrain/issues/98
> Labels: bug, frontend | Milestone: 없음
> 생성일: 2026-05-24

## 목표
채팅 메시지 전송 시 API 오류(401)가 발생해도 /login 리다이렉트 없이 인라인 에러 메시지를 표시한다.

## 루트 코즈
1. `lib/api.ts` — 401 수신 시 `window.location.href = '/login'` 즉시 실행 (try-catch보다 먼저)
2. `RouteGuard.tsx` — `/login`에서 `user && isPublic` 조건 시 `/chat` 재리다이렉트
3. 결과: chat → login → chat 루프

## 관련 파일
- `lib/api.ts` — `apiFetch` 401 핸들링
- `app/(main)/chat/page.tsx` — `handleSubmit` (session 생성 + message 전송)

## 작업 분해
- [x] `lib/api.ts`에 `skipAutoRedirect` 옵션 추가 — true 시 401을 `{ status: 401 }` throw만 수행
- [x] `chat/page.tsx` handleSubmit의 세션 생성·메시지 전송 apiFetch 호출에 `skipAutoRedirect: true` 추가
- [x] handleSubmit catch 블록에 `status === 401` 케이스 추가 — 인라인 에러 메시지 표시

## 완료 기준
- 채팅 전송 중 401 응답 시 /login 리다이렉트 없이 채팅창에 에러 메시지 표시
- 인증이 없는 상태에서 /chat 직접 접근 시 기존 RouteGuard 리다이렉트는 정상 동작
